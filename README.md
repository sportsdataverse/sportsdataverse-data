This repository is the **release store** of the
[SportsDataverse](https://sportsdataverse.org): the `load_*()` functions
in the SportsDataverse R packages and in `sportsdataverse-py` read their
data from the GitHub releases published here (the nflverse-parity NFL
loaders read the nflverse-data releases instead). This page shows how
fresh each release is, which repository produces it, and whether the
pipelines behind it are passing.

Live status:
[sportsdataverse.org/status](https://sportsdataverse.org/status) ·
nightly snapshot:
[`status/ecosystem.md`](https://github.com/sportsdataverse/.github/blob/main/status/ecosystem.md)

## Data releases

Every processed dataset is a GitHub release of this repository, tagged
by dataset name and grouped below by sport and by the repository that
produces it. Above each table are that producer’s badges: its
**pipeline** state, when its play-by-play data was last **updated**, and
the latest season it runs **through** (see [How to read the
badges](#how-to-read-the-badges)).

In each table, **Last updated** reads the release’s `timestamp.json`
asset live; a release without one shows the date of its newest asset in
the nightly snapshot. **Through season** is the newest season in the
release’s asset names. Release tags with no data assets yet are listed
at the end.

## How to read the badges

  - **pipeline** reads `fresh`, `idle (off-season)`, `stale Nd` or
    `failing`. *Idle* means the producer is outside its season window
    (see [Update schedule](#update-schedule)), not that it is broken;
    idle never turns a badge red. *Stale* means it is in season and its
    play-by-play has gone longer than its threshold without a new asset.
    *Failing* means the latest run of one of its update workflows failed
    after its newest data landed.
  - **data updated** and **through** follow the producer’s play-by-play
    tags, so a schedule file published ahead of a season does not
    advance them and an unrelated daily output cannot hide stalled
    play-by-play.
  - A **workflow badge** shows that workflow’s latest run and its date
    (`passing · date`, `failing · date`, `disabled · date`), whatever
    event triggered it.
  - Every badge is rebuilt nightly from the status snapshot. The
    exception is the **Last updated** column under [Data
    releases](#data-releases), which reads each release’s
    `timestamp.json` live.

## How the pipeline works

``` mermaid
flowchart LR
  API["Source APIs<br/>ESPN, NBA/WNBA Stats, NFL Next Gen Stats,<br/>NHL, PWHL, MLB, stats.ncaa.org"]
  RAW["*-raw repo<br/>scheduled scrape"]
  DATA["*-data repo<br/>R and Python processing"]
  REL["sportsdataverse-data releases<br/>parquet, csv, rds + timestamp.json"]
  LOAD["load_* functions<br/>R packages and sportsdataverse-py"]
  API --> RAW
  RAW -->|"repository_dispatch"| DATA
  DATA -->|"upload"| REL
  REL --> LOAD
```

1.  **Scrape** — the `*-raw` repository runs on a seasonal schedule and
    captures fresh JSON from the source API. Sources that block
    datacenter IPs or need a strict rate budget are captured from the
    SportsDataverse droplet instead of GitHub-hosted runners.
2.  **Dispatch** — a [trigger workflow](#trigger-workflows) fires a
    `repository_dispatch` event at the matching `*-data` repository;
    some producers run on their own schedule instead.
3.  **Process and publish** — the producer builds the datasets and
    uploads them here as release assets, one release per dataset. For
    example, `cfbfastR-cfb-raw` captures ESPN college-football games and
    `cfbfastR-cfb-data` builds and publishes every `espn_cfb_*` release.
4.  **Consume** — the R packages and `sportsdataverse-py` read those
    release assets through their `load_*()` functions.

inside it a producer reads *stale* once its play-by-play goes longer

## Dormant and archived datasets

Some data repositories in the SportsDataverse organization are **not**
on an active schedule and are kept for archival access only — for
example `sportsdataverse-baseball-data`, `softballR-data`,
`sdv-racing-data-repository`, and the archived `hoopR-data` and
`wehoop-data`. In this repository the `phf_*` releases are a frozen
archive (the PHF ceased operations in 2023), and `nhl_xg_models` has no
public producer; both are listed under *Unattributed releases* above. A
release whose *Last updated* date is well behind its producer’s badges
is likewise no longer being refreshed. Treat data from these as
historical snapshots.
